# 引擎迁移干员路径对照

日期：2026-10-29。AUE 基线：`b25523619c981cb1380928ffe96b0fcd67263e74`。范围为当前实际可选的 205 个槽位，使用牌库记录的 `charId` 和 `kitRef`，不使用注释中的第一个角色 ID 推断注册身份。

## 结论

当前牌库分为 72 名 AUE 默认启用 kit、121 名默认走原生实现、9 名补位和 3 名自设。本轮补齐的是这 205 个槽位的数据及源码入口对齐，不是行为等价认证。

121 名对应的 300 个技能，在 AUE 同一干员的数据记录中都能找到同 ID、同等级的条目。9 名补位也全部有 AUE 数据记录，共对应 25 个技能；“AUE 没有补位数据”不成立。三名自设的 9 个技能 ID 不在官方记录里，符合它们是项目独立内容的事实。

这说明当前主要障碍是执行语义和接入，而不是缺少这批原作技能的数据文件。不能据此判断它们已经与本地手写 kit 等价。

## 原生实现的实际范围

AUE 的原生路径由 `operatorAt`、`skillDefOf`、技能文本解析、天赋和模组处理、召唤物内容构建及模拟运行时共同组成。不是只把 blackboard 填进一份倍率模板。

赫默就是可明确追踪的例子：本地 `chess_char_2_02-silent.js` 包含医疗无人机补给、库存满时阻回、医疗职业光环和模组治疗处理；AUE 的 `tokens.js`、`summontext.js` 有召唤物库存补给和持续时间解析，`matchContent` 会构建她的召唤物内容。因此“召唤类通用实现必然缺失”没有依据。补库存、库存限制、阻回、治疗和离场必须分别核对，不能用其中一项存在代替整套机制成立。

AUE `matchContent(match, {source, kits})` 接受传入的 kit 工厂；72 名白名单是默认 `loadKits` 的筛选条件，不是内容入口的绝对上限。是否保留本地实现，要根据兼容层的导入与运行契约决定。

## 数据差异的含义

121 名的 300 个技能中，15 个技能出现基础字段原始表示差异，均涉及本地 `ON_DEPLOY` 与 AUE 数据中的数值 `8`；这只是原始字段的比较，实际触发语义要继续沿转换与执行分支确认。

另有 5 个技能的数值 blackboard 不同，涉及 `range_id`、`projectile_range`、`talent@token_key`。本工具只比较数值 bb，字符串信息和运行时解释不在该比较结论内，不能把“本地数值 bb 没有”解释成技能效果缺失。

天赋、模组、召唤物、伤害结算、持续时间和玩家操作没有因为技能参数相同就自动得到保真结论。

## 可复现的证据索引

工具：`tools/report-operator-paths.mjs`。默认读取同级 AUE 目录，也可用 `--aue` 指定。它只解析源码与 JSON，不导入任一引擎，不启动战斗；AUE 提交不符合固定基线时停止生成。

```powershell
node tools/report-operator-paths.mjs > .agent-runs/aue-operator-paths.json
```

报告逐槽位列出实际身份、默认执行类别、注册键与源码行、全部技能的描述和 blackboard、技能等级、原始参数差异、召唤物引用及当前模组是否在 AUE 中存在。输出只用于定位证据，不能替代执行语义对比。生成目录为项目内忽略的研究记录，不作为玩家运行依赖。
