# 表现事件清单

本文件是引擎向画面发出的**表现事件**的规格。用途有两个：

1. 接入新引擎（如 AUE）时，这是"必须还原哪些事件"的验收清单；
2. 给上游提 issue 的材料——AUE 的兼容层 `ShBattle.fx()` 目前是空函数，本项目全部表现都挂在同名入口上。

统计口径：`grep -o "\.fx('[A-Za-z0-9_]*'"` 扫描 `public/` 与 `server/` 下的 `.js`，共 **186 个事件名、615 次调用**（必须带前导点：不带点会把 `sfx('click')` 这类音效调用也算进去，多出 13 次、若干假事件名）。
事件只从模拟侧发出、由表现侧消费，方向单一：**画面永远不反向推动伤害或技能结算**。

## 事件形状

所有事件都走同一个入口：

```js
battle.fx(kind, params)     // kind 是字符串事件名，params 是对象
```

消费端在 `public/js/render/app.js` 的 `case kind:` 分支与 `public/js/render/fx/` 下的自设模块里。渲染器不认识的事件直接丢弃，所以**新增事件必须先加消费端**，否则是静默失效。

`params` 里最常见的字段（按出现频次）：`x`、`y`（格坐标）、`id`（单位 ID）、`n`（数量或层数）、`r` / `radius`（半径）、`tiles`（格子键数组）、`src`（来源单位）、`target`（目标）、`kind`（子类型）、`dur` / `duration`（持续时间，秒）、`skill`（技能 ID）。

## 迁移验收怎么用这份清单

1. **先还原前 30 个通用事件**。它们覆盖了绝大多数干员的常规表现；缺一个，对应的一批干员会变成"打得出伤害但看不见效果"。
2. **再逐个还原创作者内容**。上表 21 个自设事件是硬门槛：任何一个接不上，等于对应干员的表现报废。
3. **不要用"画面能跑"作为验收**。事件是单向广播，渲染器丢弃不认识的事件不会报错；必须逐条对照本清单确认消费端存在且被触发。
4. `battle.fx` 是接口契约，不是实现细节。新内核若没有等价入口，需要一层显式桥接，**不允许**让特效模块反过来读引擎内部状态来"猜"该画什么。

## 维护约定

- 新增事件：先在消费端加分支，再在模拟侧调用；两处都要有注释说明触发条件。
- 删除事件：先确认消费端没有引用，再从模拟侧移除。
- 本清单不是手写维护的：改动后用 `grep -ro "\.fx('[A-Za-z0-9_]*'" public server | sed "s/\.fx('//;s/'//" | sort | uniq -c | sort -rn` 重新统计，与本表对照。注意正则前面的点。
