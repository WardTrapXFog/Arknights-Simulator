# 训练场构想

**状态：设想，待实现。** 本文记录方向与优先级，不承诺时间。

## 要解决的真实痛点

集成战略里，想练一个 boss 关，得先打一小时才走到那一步——走完还可能被初见杀，再来一小时。玩家真正想要的不是「完整跑一遍流程」，而是**反复练那一个关键局面**。

这个项目最初的定位是「能玩自制关卡的模拟器」，但如果补上三件事，它就能变成一个**训练场**：

1. **能快速到达任意关卡**（不用打前置）；
2. **能按自己的实际情况调难度**（不是满配，是我这队的练度）；
3. **能反复试错并看到反馈**（失败成本接近零）。

第 1 条已经基本成立——导入关卡 JSON 即可直接开打。第 3 条是天然的（这就是模拟器）。**第 2 条是当前的短板。**

## 现状与缺口

| 维度 | 现状 | 对训练场的影响 |
|---|---|---|
| 关卡准入 | 直接导入 / 目录读取 / URL 导入 | ✅ 已满足 |
| 难度可调 | 只能改 `meta.difficulty` 这个粗粒度数字，以及手填 `spawns[].mods` | ⚠️ 离 tomimi 那种「难度/debuff/紧急-普通」开关很远 |
| 干员练度 | **全员满配**（最高精英化、满级、满潜、满信赖、技能满级、三级模组） | ❌ **严重扭曲判断**：用满配打“我能不能过”，答案永远偏乐观 |
| 干员覆盖 | 202 名官方干员 + 3 名自设 | ⚠️ 缺联动干员（版权）、缺部分新干员。但训练场只打特定关，实际用到的池子很小 |
| 卫戍协议视觉 | 还留着几阶标识之类的原玩法元素 | ❌ 与本项目无关，应删 |

## 优先级（按「每一步单独都有价值」排）

### ① 练度档 —— 最高优先

没有它，这个工具回答的是「满配能不能过」，而不是「我能不能过」。

- 档位：精一满 / 精二 1 级 / 精二 60 级 / 满配
- 叠加：潜能 0–6、技能等级 1–7 与专精、模组 0–3
- 数据基础已验证：`data/gamedata/character_table.json` 的 `phases[].attributesKeyFrames[]` 含每档血量/攻击/防御；技能参数在 `skill_table`，潜能在 `potentialRanks`，模组在 `battle_equip_table`
- 官方干员记录只有一个 `status`（如精一 55 级），没有多档 `forms`，所以需要按档位**现算**而不是现取

### ② 关卡难度面板

编辑器里加一组控件，对齐 tomimi 的体验：主题 → 难度等级 → 紧急/普通 → 环境（如黑流地脉）。设计细节见 [关卡自动复刻设想](关卡自动复刻设想.md) 的「主题档案」一节。

关键取舍：关卡文件里**同时**存语义（`meta.grade/emergency/environments`）与折算结果（`spawns[].mods`），两者不一致时可由生成器重算。

### ③ 批量复刻器

六主题共 775 关（90/97/99/127/178/184）。用「主题档案 + 通用生成器」把它们批量变成可玩关卡，详见 [关卡自动复刻设想](关卡自动复刻设想.md)。数据来源与两个坑（`list_stages` 不含 ISW、紧急倍率逐关不同）都已实测记录。

### ④ 训练反馈

失败次数、最佳用时、卡在哪一波。属于锦上添花，等前面三项有实际用户再说。

## 关于「要不要做得这么完美」

明确的取舍：

- **干员数量不必求全。** 训练场的用法是「打这一关」，用到的干员池很小；全图鉴是收藏需求，不是训练需求。缺谁就补谁。
- **练度必须可调。** 这是训练场成立与否的分水岭，比多接 50 个干员重要得多。
- **卫戍协议的视觉残留直接删。** 那个阶数标识属于另一个玩法的语言，留着只会让人误以为这是卫戍协议模拟器。

## 现在不做

没有外部用户之前，先保证「能玩、能改、能分享」这条链路稳定。上面四项等真的有人抱怨「打不过但不知道是不是自己的问题」时再动手——那时需求会更清楚。
