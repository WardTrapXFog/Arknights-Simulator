# 引擎迁移工作清单

日期：2026-10-28。前置评估见 [AUE 引擎迁移评估](AUE引擎迁移评估.md)（快照 `b255236`，v0.1.4）。

本清单把评估的结论落成可执行的任务：**先收口会话边界（B 线），再决定是否接 AUE 内核；素材索引瘦身（C 线）与 B 线并行，不依赖迁移结论。**

## 0. 已定的判断

| 议题 | 结论 | 依据 |
|---|---|---|
| 是否整仓迁移到 AUE | 否。保留页面、关卡文件、沙盒存档与内容定义，只在会话边界后面换内核 | 评估 §1、§6 |
| 是否先换渲染器 | 否。渲染是独立决策，必须排在机制适配成立之后 | 评估 §8.5 |
| 是否做通用干员制作器 | 否。见 §4 | 本文件 §4 |
| 素材索引瘦身 | 做，且与 B 线并行 | 本文件 §3 |

## 1. B 线：会话边界收口

目标：界面不再读引擎内部字段，只经一个会话门面取数据、下命令。**这一步的价值与最终换不换 AUE 无关。**

### 1.1 现状（已核实）

| 位置 | 依赖的引擎内部 |
|---|---|
| `public/sandbox/js/battle-session.js` | `_checkEnd`、`_remove`、`_createAllyFromInput`、`_deploy`、`_setupUnit`、`_processSpawns`、`_queueSpawn`、`_pending`、`_occ`、`hand`、`players[0].dp` |
| `public/sandbox/js/controller.js` | `_createAllyFromInput` + `_deploy` 直调、`battle.hand` |
| `public/sandbox/js/battle-runner.js` | `battle.snapshot()`、`battle.drainEvents()`、`battle.step()`、`battle.forceEnd()`、`battle.heal` 猴补 |
| `public/sandbox/js/field-view.js` | `battle.time`、`battle.rect`、`battle.fieldMeta()` |
| `public/sandbox/js/damage-score.js`、`battle-feedback.js`、`enemy-placement.js`、`save.js` | 单位 `mem`、`s`、`buffs`、刷怪入口 |
| `public/sandbox/js/ui/level-result.js` | `run.levelId`、结算快照 |

改名前先记一条：`battle.fx(...)` 一类表现调用共 **631 处、散在 188 个文件**，它们**不**属于本线——那是表现契约，见 §1.4。

### 1.2 门面要覆盖的能力

`public/sandbox/js/session.js`（新建，纯转发，不含规则）：

- 生命周期：`create(document, mode)` / `start()` / `step(n)` / `dispose()`
- 推进：`play()` / `pause()` / `speed(v)` / `advance(seconds)` / `finished`
- 命令：`deploy(input)` / `retreat(uid)` / `skill(uid)` / `spawn(input)` / `removeSpawn(tag)`
- 查询：`time` / `players()` / `units()` / `board()` / `cost()` / `life()` / `hand()`
- 观测：`snapshot()` / `drainEvents()` / `result()` / `score()`
- 存档：`captureScene()` / `restoreScene(saved)`（沿用现有"只恢复选定状态"的承诺，不扩成完整战斗恢复）

门面内部可以读 `_pending` 之类的私有字段，**外部不允许**。收口的验收标准是：`public/sandbox/js/` 下除 `session.js` 外，**零处**出现 `battle._`、`battle.hand`、`battle.players`。

### 1.3 分步

1. 建 `session.js`，先把 `battle-session.js` 现有的建场/部署/存档恢复搬进去，行为一字不改。
2. `battle-runner.js` 改为对门面发命令，不再直接 `battle.step()`。
3. `controller.js`、`field-view.js`、`damage-score.js`、`battle-feedback.js`、`enemy-placement.js`、`save.js` 逐个改读门面。
4. 用一条 grep 断言守住边界（写成 `tools/check-session-boundary.mjs`，接进 `npm run levels` 同一类校验习惯）。
5. 全部改完后，`battle-session.js` 只保留 `export const battle` 的兼容出口，便于回退。

分步之间每一步都能独立运行；任何一步卡住都可以停在这里，不回退已完成的。

### 1.4 表现契约（B 线的附带产物）

把 631 处 `battle.fx('…')` 的字符串与参数形态整理成一份清单（`docs/表现事件清单.md`），作为"引擎必须向画面发出哪些事件"的规格。它同时是给上游提 issue 的材料——AUE 的兼容层 `fx()` 目前是空函数。

## 2. 迁移判定点（做完 B 线之后才启动）

只在 B 线完成后评估，评估材料是三个困难样本的**静态对账**，不是"能不能跑起来"：

| 样本 | 要对的账 |
|---|---|
| 塔露拉 | 起飞/焰浪/持续地块的机制依赖；全部 `battle.fx` 事件与参数 |
| 结城理 | 三套 `SkillRuntime` 实例、人格与费用消费、装备操作、特殊退场的等价实现路径 |
| 望 | 库存、顺序跟子、三技能朝向、声音事件 |

判定规则：若三者中任何一个必须**广泛改写 AUE 私有实现**才能接上，或兼容代码量超过现有内核实现在同一功能上的复杂度，则停止迁移，只保留 B 线的收口成果。

## 3. C 线：素材索引瘦身（与 B 线并行）

### 3.1 已核实的问题

`tools/assets/plan.mjs:593` 对 `catalog.autochessUi` **全量建叶子，没有任何白名单**：

```js
for (const [group, entries] of Object.entries(catalog?.autochessUi || {})) {
  for (const [key, url] of Object.entries(entries || {})) addUi(group, key, url);
}
```

后果（本机实测）：`public/assets/ui` 落盘 **38.7MB**，其中按文件名扫描未被任何 js/css/html 引用的约 **16.9MB / 515 个文件**。

已确认无人引用的分组（19 组，合计约 4.9MB）：`campLogo`、`modeChoice`、`shopLevelSprite`、`bandChoose`、`shopPanel`、`prepareBkg`、`bondDetail`、`itemRarity`、`eliteLarge`、`bondBoardIcon`、`stageInfo`、`equipSlot`、`chessLevelSprite`、`medalIcon`、`hudBondItem`、`charEliteSprite`、`rarityYellow`、`prepReady`；`hudPanel/bg_board.png` 是用户点名的那张"官方棋盘"——文件在，代码零引用。

另有三个大目录属于**已删除的联机界面遗留**：`settle`（5.4MB）、`loading`（3.6MB）、`entry` 的大部分（2.1MB）。`public/js/screens/` 目录已不存在（`settle.js` 缺失），但 `settle/*` 仍在下载。

### 3.2 做法（不可直接删）

路径有动态拼接（如 `ui['guide/<key>']`、`ui['entry/<key>']`、`ui[\`garrisonTypeIcon/${id}\`]`），盲删会删掉活素材。所以顺序是：

1. 在 `plan.mjs` 增加声明式白名单 `UI_GROUPS`（分组 → 用途一行注释），`autochessUi`、`ARTS_GROUPS`、`UI_EXTRAS` 三处入口都过它。
2. 写 `tools/check-ui-assets.mjs`：catalog 里出现白名单未命名的分组就报错并列出，防止将来回涨。
3. 跑一次 `node tools/fetch-assets.mjs --prune`，删掉不在新清单里的本地文件。
4. 复查三个动态拼接点（`guide`、`entry`、`garrisonTypeIcon` 等）在运行时仍可取到素材；缺了就把对应分组加回白名单。

预期回收：`public/assets/ui` 从 38.7MB 降到约 20MB 量级，下载条数同步减少。素材目录本身不入库（`.gitignore` 已忽略），所以瘦身只影响本机与玩家首次下载，不影响仓库体积。

## 4. 不做：通用干员制作器

结论：**不做"填表就能造干员"的通用制作器。**

理由（都是本项目已确认的事实）：

- 干员的成本不在数值，在机制。现有 3 名自设（塔露拉、维娜、结城理）各自带着专属 kit、专属特效事件与专属状态；结城理还要三套技能运行时。这些不是表格能表达的。
- 若把机制也做成表格，本质就是再造一套 Stronghold 的 kit API（钩子总线、定时器、Buff 规则、事件上下文）。那已经有人做完了。
- 外观更卡死：AUE 的数据 mod 明确**不能**新增敌人、召唤物、攻击范围，也不能带自有图片、模型和声音，新干员只能借用官方外观。我们的自设素材是自制图片＋自制特效。
- 参考实现：AUE 的 `docs/mods.md` 已把"填表"这条路走到了它的上限——改数值、加干员（借外观）、改关卡。那正是"填表可行"的边界，而它不能满足本项目对自设的定义。

替代路径（若将来确有需要）：直接兼容 AUE 的数据 mod 格式，而不是自造一套。这样能白拿它的校验、打包与加载链，且不引入第二种内容格式。

## 5. 顺序与停止条件

1. 建门面 `session.js`（行为不变）→ 2. 逐个 UI 改读门面 → 3. 边界断言进校验 → 4. 整理表现事件清单。
5. C 线可全程并行，但白名单与校验脚本要先于 `--prune` 落地。
6. §2 的静态对账只在第 1–4 步完成后启动；结论是"不迁移"也算完成，B 线成果照留。
