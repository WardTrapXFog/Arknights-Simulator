# 引擎迁移成果与维护

## 一、解耦与模块化

页面继续通过 session.js 查询战况和发出操作。建场选择、数据读取、AUE 内容转换、旧形状投影及本地内容兼容分别落在会话、battle-data.js、aue/content.js、aue/battle.js 和 aue/sh/。旧建场流程移入延迟加载的 legacy-session.js。

默认加载链不再提前加载旧 Battle。静态导入检查中，会话入口和 AUE 适配器均不导入 server/sim/Battle.js；显式旧引擎入口会导入它。页面已缓存的数据直接复用，不再通过旧通用加载器重新请求一份，也不加载旧脚本与特质安装器。

内容与表现分开维护：现有 kit 保留技能规则，适配层把执行接口接到一个 AUE 世界；现有渲染器继续消费单位投影和事件。界面仍依赖 mem、skill、s 等既有形状，因此这次完成的是引擎替换和职责分离，并未宣称界面已经完全独立于单位数据契约。

## 二、迁移后的功能

| 内容 | 当前结果 |
|---|---|
| 自由沙盒 | 保留现场、手动投放、重复干员、手牌和存档；补齐本地敌人能力接线 |
| 游玩自制关卡 | 保留关卡、13 人编队、费用、部署、再部署、计分和结算 |
| 关卡制作器 | 保留界面和关卡格式，没有重写编辑逻辑 |
| 原有 205 个槽位 | 保留本地机制，其中包含三名自设 |
| 新增原生槽位 | 增加 259 个，共计 464 个；使用 AUE 对应的原生实现 |
| 敌人 | 259 条记录均可接入；原生能力与本地能力按单位互斥 |
| 回退 | ?engine=legacy 显式选择旧引擎，主要用于既有内容对照 |
| 当前验收 | 用户初步试玩后同意提交当前迁移；后续局内问题按实际反馈修正 |

没有有意删除现有玩家功能。用户试玩发现的高台部署、产费表现及本轮查明的共用适配差异，已按[回归核对](引擎迁移回归核对.md)落实修正，尚待试玩。新增槽位的机制完整度沿用固定 AUE 实现的实际边界；没有把“存在数据”写成“完整还原”。高级地形的拒绝范围和现场恢复范围见运行记录。

新增干员的模型、头像、半身图、技能图标、职业与模组图标及战斗音频进入现有素材下载计划。下载后的可用文件写入 `data/assets.json`，只添加干员数据不能让旧素材索引自动拥有新条目。素材继续由 `npm run assets` 下载；源码只提交索引，不提交官方素材文件。维护时可用 `--art-only` 只补图片与模型，已有音频继续复用，普通下载仍包含音频。新增干员也进入必需素材缺失报告，不再只统计上游原始名单。

AUE 的发布方案同样不把游戏素材收入代码仓库，而是在 Release 提供完整包和素材包（其 ADR 0062）；渲染器读取素材清单。本项目保留自己的渲染器及素材下载方式，不直接替换成 AUE 的素材清单格式。已有完整立绘登记保持原样，新增干员没有完整立绘登记时使用已下载的半身图。

## 三、源码与素材体积

UI 索引从 639 项减为 212 项，移除 427 项明确不再使用的素材，包含 hudPanel/bg_board 官方棋盘底图。本地删除对应 427 个文件，回收 15,829,066 字节，约 15.1 MiB。下载计划和索引守卫同步排除这些条目，后续下载不会重新加回。

AUE 交付只携带运行导入闭包与许可，不包含上游页面、测试、构建环境和整套训练数据。源码包约 1.2 MiB，运行文件以包内清单为准；完整上游训练数据只用于维护时生成新增牌库。

相对 5aa2674，仓库非忽略文件的原始字节总量本轮净增约 3.3 MiB，主要来自引擎源码包和新增干员数据，不能把素材回收量当作 Git 仓库减小量。计量工具按当前 HEAD 与工作区非忽略文件的原始字节数比较，结果写入 .agent-runs/engine-footprint.json；该口径不是 Git 压缩包、下载流量或历史体积。

旧内核非内容文件目前保留 38 个，合计 648,686 字节，约 0.62 MiB。其中部分纯函数仍由数据、投影和内容适配使用，旧引擎也保留为验收对照；未为追求文件数提前删除。后续删除应以实际引用和用户验收为依据。

## 四、后续同步 AUE

可以只同步引擎及内容运行依赖，不合并上游的项目结构、页面或启动方式。当前固定版本由 public/sandbox/js/aue/version.js 指定，维护工具从只读 AUE Git 对象提取 math、schema、sim、content，并按运行导入闭包生成交付包；本项目三模块、自设、关卡与存档不由上游覆盖。

维护顺序为：

1. 在可读的 AUE 仓库中备好待采用的提交，先核对兼容接口与机制变化，再修改固定提交。
2. 运行 npm run engine:prepare，可用 -- --source 指定 AUE 来源目录。工具更新适配器中的固定版本 URL、源码闭包、哈希和许可，不写上游仓库。
3. 运行 npm run engine:roster，更新新增原生干员及配装数据。原有 operator-library.json 和自设内容不由此覆盖。
4. 针对上游变化做有限检查并试玩，再将版本、源码包、牌库和相关适配一并交付。

这支持受控的局部同步，不等于可以无审查地自动更新。公开接口变化、本地 kit 的桥接、元素模块内部导出及费用回调的生成位置仍需核对；升级时应保留上一份可运行版本供对照。普通玩家只接收已准备好的源码包，不参与维护构建。
