# AUE 试接方案与兼容性审查

日期：2026-10-29。AUE 固定为 `b25523619c981cb1380928ffe96b0fcd67263e74`，其 kit 源固定为 Stronghold `b3deebdae4a92642c007d217a1a4573e5d3612c5`。本项目内容取当前工作区。数据入口的全量定位见[干员路径对照](引擎迁移干员路径对照.md)。

## 接入结论

本地默认路径已接入 AUE。原有干员保留本地机制，没有把 121 名原作同时切成原生实现；新增 259 个原生槽位，总计 464 个。三模块页面、渲染器、关卡文件和沙盒存档保留，旧引擎只在显式回退时装载。

这条路线保留机制源码作为对照，分别解决内核接入与内容简化。以后只有完成逐技能、天赋、模组、召唤物及玩家操作对照的干员，才撤去本地 kit，转用原生路径。全量数据与导入审查已经完成；全量行为等价没有成立，不能将本次报告用于宣布正式迁移完成。

目前的解耦已经收口调用位置，但尚未收口返回数据：`session.js` 返回的单位仍带旧引擎的 `mem`、`skill`、`s`，`panel-models.js` 和 `field-view.js` 仍读取这些字段。因此“只改 session 一个文件就能换引擎”不成立，旧形状投影与表现事件现由 aue/battle.js 提供，彻底引擎无关的数据契约仍需另行收口。

## 全量内容的处置

| 内容 | 当前数量 | 试接规则 |
|---|---:|---|
| AUE 默认启用 kit 的原作干员 | 72 | 其中 60 份与固定 Stronghold 源文本一致，12 份有本地修改；保留修改的明确行为，不能先覆盖后找回 |
| 本地有 kit、AUE 默认走原生的原作干员 | 121 | 300 个技能均存在同 ID、同等级的 AUE 数据；先保留本地 kit，经接口适配后接入 |
| 补位干员 | 9 | 25 个技能均有 AUE 数据；保留其自己的身份和本地机制，不恢复上游自动棋的替身关系 |
| 自设干员 | 3 | 保留已确认数值、机制、模型、音频与专属表现；不得用官设角色记录替代 |

121 名的原生路径并非只有倍率模板：`content/src/operators.js` 组合训练、模组、天赋；`traits.js` 处理分支和角色特性；`skills.js`、`skilltext.js` 转换技能数值和文本；`tokens.js`、`summontext.js` 生成召唤物和补充规则；`sim/src/skills.js` 选择被动、弹药、持续、下次攻击或瞬发分支。部分召唤物确有原生支持，不能按“存在召唤物”直接判缺失。反之，同技能 ID、同数值和同描述也不能证明钩子顺序、失败分支、状态解除、手动部署或归因相同。

300 个技能中的 15 项原始基础字段差异均涉及 `ON_DEPLOY` 与数值 `8`：本地构建器将 `8` 命名为 `ON_DEPLOY`，AUE 兼容记录将其转为 `NONE`，原生技能 SP 转换未识别时为 `none`。这说明存在表示转换，不能据此宣布被动触发等价。另 5 项数值 blackboard 差异涉及范围或召唤物字符串标识；必须连同字符串字段与范围表一起读取，不能把数值项缺失判作效果缺失。

## 导入契约审查

`tools/report-kit-contracts.mjs` 对全部 205 个槽位追踪本地内容导入闭包，并对照 AUE `compat/mapping.js` 的具名导出。它不加载 kit、不启动引擎。结果如下：

| 类别 | 未发现所覆盖的静态导入障碍 | 含缺失导出、未映射模块或占位接口 |
|---|---:|---:|
| 默认启用 kit | 59 | 13 |
| 默认原生路径 | 92 | 29 |
| 补位 | 8 | 1 |
| 自设 | 1 | 2 |

左列只说明静态导入这一层。工具不证明成员调用可用、别名接收者可用、单位读写兼容或战斗语义等价。右列同时包含会阻止加载的缺失导出，以及仅在调用时抛错的 `gap()`；共享文件导入某接口也不代表每个使用者都会执行它。

### 会阻止对应模块直接加载的三处

| 内容 | 缺口 | 接入处置 |
|---|---|---|
| 凛御银灰 | `constants.js` 缺少 `ENEMY_COLLIDER_RADIUS` 导出 | 在本项目桥接模块补充明确的碰撞语义；不能只补一个任意常数使导入通过 |
| 塔露拉 | `damage.js` 缺少 `elementBurst` 导出 | 将自设的强制元素爆发调用接入 AUE 元素流程，保留爆发锁、来源与冷却规则；不以额外普通伤害冒充爆发 |

### 导入通过以后仍缺少的 SI 契约

对本地内容中显式 `battle.x` 的 AST 引用与 `ShBattle` 声明成员作对照，已经定位 `hand`、`flags`、`siLevel`、`canSpendDp`、`_setupUnit`、`redeploy`、`kill`、`pull`、`pullToFront`、`removeStatus` 等适配线索。附录按干员列出；此扫描不覆盖别名和动态扩展，也不把共享文件中未执行的函数计为必然故障。

最关键的不是给这些名字全部加空函数，而是保留其职责：手牌库存、补充队列、费用预留、真实撤退与再部署、召唤物归属、主题开关、位移路径、状态移除。AUE `getPlayer()` 返回的 `dp` 是 getter，也没有本项目的 `dpFloor` 状态，不能把旧代码写玩家对象视为已经改到了新世界。

## 三模块、存档与表现的完整边界

| 边界 | 已确认事实 | 试接方案 |
|---|---|---|
| 关卡制作器 | 输出 SI 地形、路线、出生表与 `meta` | 保留编辑器和磁盘 JSON；仅在建场时转换为 AUE Content |
| 关卡游玩 | 13 人编队；费用、冷却、部署与生命上限；结束条件与报告 | 外观与编队数据不改；新会话映射命令、结果与计分；不使用标准 match 的 12 人校验来裁掉第 13 人 |
| 自由沙盒 | 可重复部署同一干员、任意刷怪、原地钉住、改地形重建、无自动结束 | 为各实例分配独立内容键／运行身份；不是重复使用同一个 `charId#seat`；敌人操作与结束规则单独适配 |
| 出生与路线 | SI 只能选 `spawns` 或 `waves` 一种来源 | 保留状态层的选择；转换单一路径，禁止两份队列同时进入新世界 |
| 沙盒存档 | 现场重建，保存 HP、SP、攻击冷却、时间、费用和剩余路线；当前就不保证技能／异常／弹道完整恢复 | 保持现有格式和保证范围，以新部署顺序恢复现场；不能直接塞入 AUE Snapshot |
| AUE 快照 | 钩子、定时器及兼容包装的 `mem` 不属于完整可恢复状态 | ADR 0057 已说明需要重放；不能用 JSON Snapshot 宣称恢复了自设与定时任务 |
| 渲染 | 现有渲染器消费旧快照、单位状态与命名事件 | 新建明确投影；帧换秒、数值枚举、单位 ID、方向和移除原因逐项映射，不重写现有视觉模块 |
| 角色表现 | `ShBattle.fx()` 当前为空；186 个命名事件有 615 次调用 | 将 kit 的 fx 与 AUE 原生表现事件合并到每帧单次消费队列，避免重复播放；不得通过丢弃事件维持可运行 |
| 自设表现 | 三名自设有 19 个专属事件，望另有 2 个修正事件 | 保留现有消费端，并显式投影所需状态；不能期待 AUE 自带这些表现 |
| 火力计分 | 当前统计实际伤害回调、来源归属、四类伤害与近 5 秒 DPS | 从新引擎真实结算事件接入，保留召唤物归因和过量口径；不从飘字反推 |
| 结束与音频 | 成功／失败有各自过渡、音效与报告；局外音源常驻宿主页 | 仅替换结果输入和局内事件，保留 BGM 生命周期与播放缓存 |
| 敌人 | 本地 `data/enemies.json` 有 259 条；本地行为按能力与 key 接入 | 保留本地目录与数值，逐能力映射 AUE FoeBehavior；不得只迁移干员就宣布战斗迁移完成 |

AUE `foes.js` 对部分缺参数能力有 `withoutIncomplete()` 处理，这意味着“数据中存在敌人”也不等于每项能力生效。原作敌人、本地修正、木桩倍率、召唤敌人、领袖阶段、加防光环及零生命扣除漏怪均必须保留。当前导入审查覆盖的是玩家干员 kit，并未证明 259 条敌人行为等价；第一轮仅使用能力范围已明列的敌人，后续按能力登记表扩展，不拿基础敌人开局成功代表全敌人通过。

## 最短完整试接路径

1. 在本项目内准备固定版本的实验入口、源码装载与 SI 内容转换。兄弟目录 AUE 只读，不修改其源码、依赖或 Git；本地默认选择 AUE，显式 ?engine=legacy 才选择旧引擎。
2. 先接纯内核 `createWorld`／`step`。不接联机 SDK 会话、房间、WebSocket 或锁步恢复；以 SI 当前单机 runner 驱动命令与帧推进。
3. 内容工厂按 SI 关卡与实例生成 Content，保留本地标识并记录 AUE 运行身份映射；13 人与重复实例从这里解决。通过 `kitsBehaviors(entries, seen)` 的 `seen` 取得本场兼容对象，在 SI 扩展内绑定费用、手牌、标志与 fx；不改 AUE 兼容类的全局原型。
4. 补充真实调用需要的兼容导出和成员，逐项实现上文语义。三处导入硬阻塞优先处理；共享占位按真实调用路径处理，不将未调用占位误记成故障。
5. 将新世界投影为现有界面所需的只读模型和快照；接通表现队列、伤害计分、终局及现场保存。正式会话不得同时推进两个引擎或把同一命令发给两边。
6. 第一批观察范围覆盖：普通攻击／技能与部署费用、召唤物库存、望的顺序落子、思衡托的撤退／待投放、三名自设、13 人及重复实例、存档重建、成功／失败。困难样本用于检查已识别契约，不能替代全量干员和敌人登记。

首轮应能在独立入口完成“选现有关卡 → 编队 → 手动部署与技能 → 原有渲染和音频 → 原有结算”，并能进入独立沙盒部署重复干员和保存／载入现场。若只做到 Node 中推进世界，尚不构成三模块的试迁移成果。

### 错误、回退与后续简化

`loadKits` 捕获加载错误并返回 `failed`，失败角色可转原生；`ShBattle.safe` 捕获回调异常，写入 `errors` 并跳过。本地 `gameData()` 甚至会自行吞掉数据读取错误。试接入口必须拒绝未批准的原生回退、显示具体角色／阶段错误，并确保关键数据源存在；不能只以无控制台异常或战斗仍在推进判定成功。给缺口加空返回与空函数会掩盖效果丢失，应禁止。

回退以整场选择旧会话实现，不在同一场中途把 AUE 状态强行塞回旧引擎。现有内容、关卡文件和存档不做批量重写。本地默认接入已实施，提交与发布等待用户验收；某个干员能撤掉本地 kit 的决定与全场换内核分开记录。

## 依赖与部署

固定源码只在维护时通过 tools/prepare-aue-trial.mjs 从只读 AUE Git 对象提取，运行闭包和本地 kit 进入 engine/aue-runtime.json.gz，附源／转换后哈希及上游许可。生成副本额外公开元素模块已有的 burst 和 beginning，不改其算法；该内部接口依赖仍须在升级时核对。

日常启动由 tools/aue-runtime.mjs 在本地展开源码包，同一包复用缓存，不运行维护构建、不安装 pnpm、不从网络拉取 AUE。新增原生牌库由 tools/build-aue-roster.mjs 在维护时生成，保留原有牌库和自设定义。

默认页面使用 AUE；?engine=legacy 选择整场旧引擎对照，不进行场中热切换或静默回退。独立 /dev/aue-trial.html 保留地形检查；高级地形明确拒绝。

当前接入、有限检查和交付边界见 [运行记录](AUE试接运行记录.md)，局部升级流程和体积数据见 [成果与维护](引擎迁移成果与维护.md)。
