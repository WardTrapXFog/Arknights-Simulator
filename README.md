# Arknights Simulator · 关卡模拟器

基于 [Stronghold-Protocol](https://github.com/sganggs/Stronghold-Protocol) 战斗引擎的单机模拟器，分为自由沙盒、游玩自制关卡、关卡制作器三个模块，不含大厅、房间或联机。

**运行前请先安装 [Node.js](https://nodejs.org/zh-cn/download)，版本须为 22 或以上，可选择官网的 LTS 安装包。安装时保留自带的 npm，安装完成后重新打开终端。**

不熟悉 Git 也可以在本页上方点击「Code → Download ZIP」下载源码，再解压到自己的文件夹。下面介绍的是源码版的安装方式。

## 与上游的关系

战斗引擎、渲染层与大部分干员数据来自 [sganggs/Stronghold-Protocol](https://github.com/sganggs/Stronghold-Protocol)（《明日方舟》限时玩法「卫戍协议：盟约」的非官方复刻）。本项目在该引擎之上做了单机化改造：

- 去掉大厅、房间与联机，只保留单机三模块；
- 作战规则按单机关卡重写（再部署、漏怪判负、关卡自带部署上限与作战音乐）；
- 新增关卡制作器与关卡 JSON 格式；
- 新增三名自设干员与若干自制敌人。

**干员覆盖**：上游实现的是卫戍协议玩法，本项目在其基础上接入满配原作牌库，目前提供 202 名原作干员和三名自设干员。可用名单以模拟器中的牌库为准，尚未覆盖全图鉴。

## 获取官方素材

这一步为模拟器补充官方干员与敌人的图片、战斗模型、语音、音效和界面素材，让单位能够正常显示并发声。脚本从社区维护的公开资源下载文件，**不要求电脑上安装《明日方舟》，也不需要登录游戏账号**。

以下以 Windows 为例。打开解压后的项目文件夹，确认能看到 `package.json` 和 `启动模拟器.bat`：

1. **先双击 `启动模拟器.bat`。** 首次运行会自动下载安装缺少的程序依赖，完成后启动服务并打开浏览器；无需手动输入依赖安装命令。请等待安装完成，再关闭启动窗口。
2. **（非必选：做完第一步已经可以直接使用模拟器核心功能，大多美术素材会以初始模板替代）** 在项目文件夹窗口的地址栏输入 `cmd` 并回车，输入下面这一条命令，下载官方素材。已经准备好素材时可以跳过。

   ```bash
   npm run assets
   ```

3. 下载完成后，重新双击 `启动模拟器.bat` 即可游玩。以后通常只需双击启动。

| 操作 | 做什么 | 什么时候需要 | 网络与大致体积 |
|---|---|---|---|
| 首次双击 `启动模拟器.bat` | 自动安装运行所需的程序库，并准备浏览器要用的前端库，然后启动服务 | **首次使用时执行**；依赖已安装时跳过自动安装步骤 | 安装依赖需要访问 npm 软件源。当前锁定依赖的压缩包合计约 **25 MB**，另有索引等请求；已有缓存时下载更少 |
| `npm run assets` | 下载官方图片、模型、语音与音效，保存到本项目，并更新素材清单 | **建议首次使用时执行**；素材已有时可跳过，缺失或需要更新时再执行 | 需要访问 GitHub、jsDelivr 等素材源站。当前清单中的素材文件合计约 **760 MB**；索引、缓存及处理前文件还会增加流量与占用，建议至少预留 **1 GB** 素材空间 |
| 日常双击 `启动模拟器.bat` | 启动本机服务并打开浏览器 | **每次游玩需要启动** | 依赖与素材准备好后，本地关卡的日常启动与游玩可离线进行；通过链接导入关卡仍需联网 |

上面的体积是当前版本的参考值，依赖版本、素材清单与已有缓存都会影响实际下载量。首次准备主要耗时在素材下载；下载失败时检查网络后重新运行同一条命令，脚本会复用已完成的素材文件，补下缺失部分。

只想先看看界面，首次双击并等待依赖安装完成后即可进入，之后再下载官方素材。素材缺失时，相应单位可能显示占位图或占位模型，部分语音、音效也会缺失。**启动器会自动安装缺少的程序依赖，官方素材仍需通过 `npm run assets` 单独下载。**

### 会不会操作本机游戏文件？

**双击启动与 `npm run assets` 均不调用本地客户端提取。** 素材命令下载网络资源、整理项目内素材，并更新素材清单。

项目另有进阶用的可选本地提取工具，用来补充公开资源中缺少的贴图、模型与特效，不属于上述安装步骤，也不是启动前提。现有提取逻辑读取本机游戏资源，将导出结果写入本项目；不修改、替换或删除游戏客户端文件，也不向游戏进程注入内容。单独使用这类工具时，还需要额外准备 Python 依赖，并为导出文件留出空间。普通玩家按上面的步骤操作即可。

### 随源码提供的素材

自设干员、自制敌人和塔露拉特效，以及 `content/music/` 中的 OGG 背景音乐随源码提供，Git 克隆或下载源码 ZIP 即可获得。局外默认选择《生命流》，可在全局设置中改选曲目；关卡编辑器也从同一目录选择作战音乐。音乐版权归各自权利人所有，不适用代码的 GPL 许可证。

## 启动

完成上面的首次准备后，双击 `启动模拟器.bat` 即可启动并打开浏览器。也可在依赖已准备好的项目文件夹中运行 `npm start`，手动访问 `http://localhost:3100`；`npm start` 本身不自动安装依赖。

双击启动时，关闭启动窗口会结束本次启动的服务端及其子进程。若提示服务端已在另一窗口运行，请关闭原启动窗口停止服务。使用 `npm start` 时仍按 Ctrl+C 停止。

开始菜单 `/studio/home.html` 提供三个入口：

- 自由沙盒 `/studio/console.html`：进入本地存档管理，继续现场或新建 8×17 基础地图，带一组出入口。
- 游玩自制关卡 `/studio/play.html`：选择或导入关卡，查看简图及敌方情报，编队后作战。
- 关卡制作器 `/studio/level.html`：编辑地形、路线及独立出生，保存、导出或打开试玩。

## 自设干员

当前已接入塔露拉、维娜·维多利亚、结城理三名自设干员，手牌名称标注「（自设）」。官设维娜与自设维娜可以同时上场。**原作结城理**由于上游项目尚未还原，暂未加入；当前牌库中的结城理是本项目的**自设版本**。

## 自由沙盒

自由放置干员、刷敌人、编辑地形、测试技能与伤害。六槽存档支持新建、命名、覆盖、删除与复制；快存覆盖当前槽位，未绑定有效槽位时使用空槽，满槽时需先选择保存位置。敌人列表与关卡编辑器共用目录，按全部、木桩、普通、精英、领袖筛选，并保留机制木桩和耐久变体。沙盒放置操作为「选手牌 → 点格子 → 选方向」，卡片上的 × 将干员移出手牌，＋ 打开牌库，职业筛选和名称搜索可快速找人。

每名原作干员提供一张满配卡，不区分普通/进阶；采用最高精英化与等级、满潜、满信赖、最高技能等级，有常规模组时按三级计算，默认模组优先沿用原棋子所选模组。三位自设沿用各自内容定义中的数值。沙盒可选入手牌的干员最多 13 名，超过 9 张时自动收紧卡片宽度；召唤物牌按机制额外生成。自由沙盒可以重复部署同名干员、强制开技能，不受回合限时约束。

右侧火力计分板按总伤害排序，最多显示 12 行，列出物理、法术、元素、真实、总伤害和近 5 秒 DPS；显示刷新间隔约 200 毫秒，DPS 按游戏时间统计。存档保存地图、手牌与技能选择，以及存活在场单位的位置、血量、技力、普攻冷却、敌人剩余路线、费用与伤害统计，载入后暂停；不恢复进行中的技能、异常状态与弹道。

地形可以导出 JSON，再从制作器的「从沙盒导入」导入；干员、敌人现场和伤害统计不转换成关卡。

## 游玩自制关卡

从关卡列表选择一关，卡片显示难度星数，右侧可打开地形简图与敌方情报；情报按敌人种类列出，不显示各类敌人的数量。支持文件、粘贴 JSON 或链接导入，可选择只在本次页面游玩或存入关卡库。通过链接导入时，对方站点需允许浏览器跨域读取。

点「开始作战」进入编队界面，按全部、先锋、近卫、狙击、医疗、术师、特种、重装、辅助筛选，配合搜索、排序、快速编队、技能选择与模组选择完成最多 13 人的阵容。四套本地编队可以命名、保存和切换。点「开始战斗」正式载入地图。

作战使用本次页面内的出战配置，不激活或覆盖自由沙盒存档。局内保留暂停、倍速、单帧、设置、技能操作与伤害面板，关闭刷怪、改图、换牌和强制开技能。部署时需将手牌拖到可部署格，再拖动选择朝向；单击手牌只查看详情。部署扣费，同一干员只允许一人在场，撤退/被击倒后需等待再部署时间；同时在场的部署上限由关卡指定，默认 8，与最多 13 人的编队上限分别计算。基地生命显示为 3，计入漏敌统计的敌人达到 3 时失败；敌人、出生队列及待触发的敌人生成安排全部清空后结算胜利。结算可再次作战、重新编队或返回列表。

## 关卡制作器

关卡定义地形、路线、敌人与出生时间，还可指定部署上限、作战音乐、集成战略主题、难度和说明；玩家在游玩时自行编队。路线模板可复用，批量投放展开为独立出生；时间轴支持拖动、多选、框选、间隔复制和撤销。SVG 推演显示敌人位置、朝向与已走/未走路线，不运行战斗。

一级界面无需滚动：侧栏切换当前工具/关卡信息，地图随可用空间缩放，关卡库自动分页；长名单、导入文本、备注与完整错误信息放在二级菜单。时间轴默认全览，缩放后用前后按钮切换时间段。保存或导出的 JSON 自动包含地形简图。「试玩」会先保存当前修改，再新开游玩关卡页面，由玩家编队。

自由沙盒当前现场、六槽存档、四套玩家编队及全局设置保存在当前浏览器的网站数据中。清除网站数据、更换浏览器或使用不同的本机访问地址，都会影响这些内容的读取。

**关卡库保存在项目的 `content/levels/` 目录中**，由游玩端与制作器共用，清除浏览器网站数据不会删除这些关卡。移动项目时请保留该目录，也可以将关卡导出为 JSON 备份或分享。关卡文件采用 v2 格式，旧 v2 中的作者阵容不再用于出战，重新导出时移除。

## 内容维护

自设干员的完整定义在 `content/operators/`，由 `index.json` 登记；自设敌人在 `content/enemies/`。改完运行：

```
npm run content                            # 全部
node tools/build-content.mjs --operator talula   # 只更新塔露拉
```

生成器写出 `data/{chess,assets,backups,enemies}.json`、`public/sandbox/js/generated-ops.js`、`server/sim/content/kits/custom-catalog.js`。

原作满配牌库由 `tools/build-operator-library.mjs` 优先读取 `data/gamedata/`，回退 `.cache/gamedata/excel/` 中的 character/skill/range/uniequip/battle_equip 官方表，以及当前已接入的棋子与补位/甄选记录生成；复用 `tools/official-unit-builder.mjs`，写出 `data/operator-library.json` 和 `public/sandbox/js/generated-library.js`，不覆盖 `data/chess.json` 的卫戍协议档位。更新官方数据后可重新运行该生成器。

复杂战斗机制在 `server/sim/content/kits/ops/`，塔露拉专属特效由 `public/js/render/fx/custom.js` 登记。

## 代码在哪

SI 自有代码与上游引擎分开维护：

- `public/sandbox/js/` 自由沙盘，`public/play/` 关卡游玩与编队，`public/level/js/` 关卡制作器，`server/sandbox/index.js` 唯一的 SI 服务端，`content/` + `tools/build-content.mjs` 数据源与生成器。
- `public/js/render/` 与 `server/sim/` 是引擎与渲染（战斗、寻路、绘制）。
- `public/studio/` 保留三模块的 HTML 入口与共用样式；上游联机平台、插件工作台和模板不随本项目分发。
- 自设运行数据由 `content/` 经生成器写入 `data/`；官方数据表的来源与用途见 [data/gamedata/README.md](data/gamedata/README.md)。
