# Arknights Simulator · 关卡模拟器

《明日方舟》非官方单机模拟器，提供自由沙盒、游玩自制关卡和关卡制作器三个模块。

## 首次使用（Windows）

1. **先安装 [Node.js](https://nodejs.org/zh-cn/download)，版本须为 22 或以上。** 可选择官网的 LTS 安装包，安装时保留自带的 npm。
2. 在本页上方点击「Code → Download ZIP」下载源码并解压，或使用 Git 获取项目。在项目文件夹中双击 `启动模拟器.bat`，等待自动安装依赖并打开浏览器。首次安装需访问 npm 软件源，当前依赖压缩包约 **25 MB**。
3. **按需下载官方素材**，具体操作见[下一节](#获取官方素材)。

以上是源码版的安装方式；以后游玩直接双击启动即可。

## 获取官方素材

**非必选：完成首次启动后已经可以使用模拟器核心功能，大多美术素材会以初始模板替代。**未下载的语音、音效可能缺失。

需要官方图片、战斗模型、语音、音效和界面素材时，先关闭启动窗口，再在项目文件夹（能看到 `启动模拟器.bat` 的位置）的地址栏输入 `cmd` 并回车，打开命令窗口，也叫终端。输入下面的命令，再按**回车**：

```bash
npm run assets
```

脚本从社区维护的 GitHub、jsDelivr 等公开资源下载素材，包括干员完整立绘。**可由 jsDelivr 提供的文件默认优先使用该 CDN**，失败时回退原始源；语音分支和 GitHub Release 下载仍使用原始源，可通过本机的 `HTTP_PROXY`／`HTTPS_PROXY` 代理访问。如需原始源优先，可改用 `npm run assets -- --asset-source=direct`。当前下载内容约 **1 GB**，另有索引、缓存和处理前文件，建议至少预留 **2 GB** 素材空间。本文体积均为参考值，版本与已有缓存会影响实际下载量。

下载和整理时会持续输出日志，耗时取决于网络和本机速度。命令结束后查看最后的汇总；若出现 `ERROR`、`FAILED` 或 `download errors`，按提示处理后重试。**中断后可重新执行同一条命令**：已完成且符合校验条件的文件会复用，缺失文件会补下；单个尚未下载完成的文件会重新下载，不支持该文件内部的字节级断点续传。

下载完成后重新启动模拟器。素材已有时无需重复下载；启动器不会自动执行这一步。

### 会不会操作本机游戏文件？

**常规启动与素材下载不要求安装《明日方舟》，不需要游戏账号，也不会提取本机客户端。**

### 随源码提供的素材

自设干员、自制敌人和塔露拉特效，以及 `content/music/` 中的 OGG 背景音乐随源码提供。局外默认选择《生命流》，可在全局设置中改选曲目；关卡编辑器也从同一目录选择作战音乐。音乐版权归各自权利人所有，不适用代码的 GPL 许可证。

## 日常启动与关闭

**游玩期间请保留启动窗口，可以最小化；结束时关闭该窗口即可。** 关闭窗口会结束本次启动的服务端及其子进程，浏览器中的模拟器也将无法继续正常使用。若提示服务已在另一窗口运行，应关闭原启动窗口来停止服务。

依赖和素材准备好后，本地游玩可离线进行；下载素材或通过链接导入关卡仍需联网。

<details>
<summary>启动提示找不到 Node.js 或版本过低？</summary>

安装或升级 Node.js 后，重新打开命令窗口并执行：

```bash
node -v
```

输出应为 `v22.x.x` 或更高版本。若版本过低，请升级；若找不到命令，请确认已完成安装并重新打开窗口。

</details>

## 交互日志

遇到「点了没反应」「切换菜单很慢」这类问题时，可以让模拟器把浏览器的操作过程打到启动窗口里，便于定位卡在哪一步。日志默认关闭，不影响正常游玩。

**开启方式（任选一种）：**

- 在双击启动时带参数：`启动模拟器.bat --debug`
- 长期使用：用记事本打开 `启动模拟器.bat`，把 `rem set "SI_DEBUG=1"` 这一行前面的 `rem ` 删掉，保存后再双击启动
- 只对当前浏览器生效：按 F12 打开控制台，执行 `localStorage.setItem('arksim-debug','1')`；改回 `'0'` 即关闭

**日志内容**：启动窗口会逐行输出带 `[浏览器 时间]` 前缀的记录，包括点击了哪个按钮或选项卡、页面切换请求、工作区实际载入的地址、新页面就绪，以及每次页面过渡的耗时。示例：

```
[浏览器 18:05:58] [SI 3.406] 导航 · 切换工作区 → /studio/play.html
[浏览器 18:05:58] [SI 3.453] 导航 · 工作区已载入 /studio/play.html
[浏览器 18:05:58] [SI 3.672] 导航 · 过渡 /studio/play.html 完成 271.2ms
```

按时间顺序对照这几行，就能看出一次点击是卡在「没有发出切换」「切换了但没载入」还是「载入后动画没收尾」。

**其他说明**：页面本身的控制台（F12）里也会同步打印同样的记录，便于连同报错一起看。关闭调试后不会产生任何日志请求。日志只写在本机启动窗口和浏览器控制台，不发送到外部。

## 自由沙盒

自由放置干员、刷敌人、编辑地形、测试技能与伤害。新建沙盒为 8×17 基础地图，带一组出入口。

### 存档管理
六槽存档支持新建、命名、覆盖、删除与复制；快存覆盖当前槽位，未绑定有效槽位时使用空槽，满槽时需先选择保存位置。

存档会保存地图、手牌与技能选择，以及存活在场单位的位置、血量、技力、普攻冷却、敌人剩余路线、费用与伤害统计，载入后暂停；不会恢复进行中的技能、异常状态与弹道。

### 干员放置
沙盒放置操作为「点选手牌 → 按需切换技能 → 点选地块 → 拖动/点击选择部署朝向」，卡片上的 × 将干员移出手牌，＋ 打开牌库，牌库中的职业筛选和名称搜索可快速找人。

每名原作干员直接提供一张满配卡：采用最高精英化与等级、满潜、满信赖、最高技能等级，有常规模组时按三级计算，默认模组优先沿用原棋子所选模组。三位自设干员（塔露拉、维娜、结城理）使用作者设定的数值与技能机制。沙盒可选入手牌的干员最多 13 名，超过 9 张时自动收紧卡片宽度；召唤物牌按机制额外生成。

自由沙盒可以重复部署单个干员、可无视技力情况强制开技能，不受回合限时约束。

### 敌人放置
敌人列表与关卡编辑器共用目录，按全部、木桩、普通、精英、领袖筛选，并留有一些机制木桩和耐久变体。

### 火力计分板（谁尽力，谁又在犯罪）
右侧火力计分板按总伤害排序，最多显示 13 行，列出物理、法术、元素、真实、总伤害和近 5 秒 DPS；显示刷新间隔约 200 毫秒，DPS 按游戏时间统计，小窗口可滚动查看。

### 沙盒与关卡制作器的联动
沙盒可以直接将地形导出为 JSON 格式，再从关卡制作器的「从沙盒导入」导入，进行进一步编辑；已放置的干员、敌人和已产生的伤害统计暂时无法转换成关卡文件。

## 游玩自制关卡

从关卡列表选择一关，卡片显示难度星数，右侧可打开地形简图与敌方情报；情报按敌人种类列出，不显示各类敌人的数量（还原鹰角的任务简报XD）。支持文件、粘贴 JSON 或 URL 链接导入，可选择只在本次页面游玩或存入关卡库。通过链接导入时，对方站点需允许浏览器跨域读取。

点「开始作战」进入编队界面，按全部、先锋、近卫、狙击、医疗、术师、特种、重装、辅助筛选（暂未实现子职业分类），配合搜索、排序、快速编队、技能选择与模组选择完成最多 13 人的阵容。八套本地编队可以命名、保存和切换。点「开始战斗」正式载入地图。

作战使用本次页面内的出战配置，不会激活或覆盖自由沙盒存档。局内存在暂停（空格暂停或鼠标点击）、倍速切换、单帧步进、设置、技能操作与伤害面板，关闭刷怪、改图、换牌和强制开技能等沙盒功能。

部署时按住手牌拖动至可部署格，再拖动选择朝向。在场的部署上限由关卡指定，默认为 8，与编队上限分别计算；目标生命上限默认为 3，累计漏敌达到该上限时失败。敌人、出生队列及待触发的敌人生成安排全部清空后结算胜利。

战斗结束后，先显示沿战场平面展开的「模拟完成」横幅，再打开结算面板，展示基本信息和结算时刻的火力计分板。可以再次作战、重新编队、返回关卡列表或直接打开这张关卡的编辑器；仅在本次页面导入的关卡会先存入关卡库再打开编辑。

## 关卡制作器

关卡定义地形、路线、敌人与出生时间；「关卡信息」中可设置部署上限（1–13，默认 8）、目标生命上限（1–999，默认 3）、作战音乐、难度星级、标签、作者和备注。星级用于展示，不直接改变敌人数值；玩家在游玩时自行编队。路线模板可复用，批量投放展开为独立出生；时间轴支持拖动、多选、框选、间隔复制和撤销。SVG 推演显示敌人位置、朝向与已走/未走路线。

侧栏切换当前工具/关卡信息，地图随可用空间缩放，关卡库自动分页；长名单、导入文本、备注与完整错误信息放在二级菜单。时间轴默认全览，缩放后用前后按钮切换时间段。保存或导出的 JSON 自动包含地形简图。「试玩」会先保存当前修改，再新开游玩关卡页面，由玩家编队。

**重要：自由沙盒当前现场、六槽存档、八套玩家编队及全局设置会保存在当前浏览器的网站数据中**。清除网站数据、更换浏览器或使用不同的本机访问地址，**可能会导致存档、编队、全局设置等信息的丢失！**

**关卡库保存在项目的 `content/levels/` 目录中**，由游玩端与制作器共用，清除浏览器网站数据不会删除这些关卡。移动项目时请保留该目录，也可以将关卡导出为 JSON 备份或分享。

## 自设干员

当前已接入塔露拉、维娜·维多利亚、结城理三名自设干员，手牌名称标注「（自设）」。官设维娜与自设维娜可以同时上场。**原作结城理**由于上游项目尚未还原，暂未加入；当前牌库中的结城理是本项目的**自设版本**。

牌库另有 202 名原作干员，尚未覆盖全图鉴，可用名单请以模拟器中的牌库为准。

## 与上游的关系

战斗引擎、渲染层与大部分干员数据来自 [sganggs/Stronghold-Protocol](https://github.com/sganggs/Stronghold-Protocol)，即《明日方舟》限时玩法「卫戍协议：盟约」的非官方复刻。本项目在其基础上改造为手动部署的单机关卡作战，移除了大厅、房间与联机功能。

## 内容维护

自设干员的完整定义在 `content/operators/`，由 `index.json` 登记；自设敌人在 `content/enemies/`。改完运行：

```
npm run content                            # 全部
node tools/build-content.mjs --operator talula   # 只更新塔露拉
```

生成器写出 `data/{chess,assets,backups,enemies}.json`、`public/sandbox/js/generated-ops.js`、`server/sim/content/kits/custom-catalog.js`。

原作满配牌库由 `tools/build-operator-library.mjs` 优先读取 `data/gamedata/`，回退 `.cache/gamedata/excel/` 中的 character/skill/range/uniequip/battle_equip 官方表，以及当前已接入的棋子与补位/甄选记录生成；复用 `tools/official-unit-builder.mjs`，写出 `data/operator-library.json` 和 `public/sandbox/js/generated-library.js`，不覆盖 `data/chess.json` 的卫戍协议档位。更新官方数据后可重新运行该生成器。

复杂战斗机制在 `server/sim/content/kits/ops/`，塔露拉专属特效由 `public/js/render/fx/custom.js` 登记。

代码位置与数据流见[架构](docs/ARCHITECTURE.md)，官方数据表说明见 [data/gamedata/README.md](data/gamedata/README.md)，其他文档见[文档索引](docs/README.md)，提交规范见[贡献说明](CONTRIBUTING.md)。
